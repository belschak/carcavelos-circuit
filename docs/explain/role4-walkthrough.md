# Role 4 walkthrough: race flow, UI, sound and online (David Belschak)

Everything around the track is Role 4: the loading page, the start screen with its three modes and the kart builder (driver, kart, tyres), the countdown, the timer and the checkpoints, the item boxes, the ghost, medals and the leaderboard, the HUD, all sound and music, the waves and surfers at the beach, and the live online race. It also owns the contracts in `Shared/` that let every module talk to the kart, and the scripts that build `Main.unity` and the Web version.

## How it works

1. **Page.** `index.html` checks WebGL 2 and WebAssembly, asks `version.json` for a newer build, shows the loading bar for the game code and menus (about half of the 50 MB), then for the campus world, which the game downloads itself as `Build/world-<content hash>.bundle` (`WorldStream`, DXT or the ETC2 phone version, cached in the browser across deploys that do not change the world, see [../history/2026-11-18-load-time.md](../history/2026-11-18-load-time.md)). "Click to play" waits until the track is ready; if the world fails twice the page shows "The track did not download" with Reload the page. A capture listener added before Unity starts swallows the key that closes "Click to play", so it never also starts the race. On a phone the touch buttons send the keys in the `KEYS` table (W, A, S, D, Space, R, Enter, E, left Shift, P).
2. **Boot.** `RaceBootstrap.Start` first waits for `WorldStream.Load()` (no world file in the Editor, in tests or in a `-worldInData` build: then it does nothing; a failed download stops here, never a fall back to the test loop). Then it tries the scenes from `RaceSettings.TrackScenesInOrder()` (Track_Campus, Track_CampusWorld, Track_NovaCampus, then the placeholder loop), loads each additively and keeps the first with a `TrackInfo`; `WorldStream.Release()` then frees the downloaded file (the loaded scene stays). It spawns the kart at the `SpawnPoint`, adds the attachments (KartAudio, Role 3's effects), calls `RaceManager.SetUp`, connects the camera, and last tells the page the track is ready ("Click to play" appears).
3. **Set-up.** `SetUp` remembers the kart's colliders, checks the checkpoints (`CheckpointValidation`), creates Role 2's `RaceRules`, loads the best lap from `CarcavelosCircuit.Best.<track>`, stretches the medal times with `MedalScaling.LoopLength`, and puts a `CheckpointRelay` on every trigger. `RaceRoster` then places every racer on its `RacerGrid` slot.
4. **Start screen.** `MapFlyover` circles over the campus. Keys 1/2/3 or a card call `TrySelectMode`, which asks `RaceModeRules.CanPick`. Any other key calls `RequestStart`, which opens the kart builder; READY calls `BeginRace`. Online, `OnlineRaceHooks.OpenLobby` opens the lobby instead.
4b. **Kart builder (18 Nov).** `KartBuilder` hides the start screen and shows three columns DRIVER | KART | TYRES (four tiles each) next to a turntable. A pick calls `DriverChoice.Select` / `SelectKart` / `SelectTyres`: a new driver keeps the kart and tyres, the set is saved in PlayerPrefs, `LoadoutChanged` makes `BotSquad` put `KartComboLibrary.Template(set)` into the player's kart (a new driver also lines the bots up again). The set's model comes from `KartAssembler`: copy Luc's prefab of the kart, swap the four tyres from the tyre's prefab (moved out/forward by any extra width/radius), swap `Driver_<Name>` from the driver's prefab (placed by the `Seat`), lift the kart so the tyres touch the ground, set `wheelRadius`, rebuild the LODGroup lists; all while switched off, so the kart scripts wake up only on the finished set. RaceFlow cannot see Visuals, so it gets models through `KartModels.Template` (set by `BotSquad`). `KartStage` is a small studio 6 km below the world: its own camera (layer 30, no post-processing, no HDR so the background stays see-through, fog off while it draws) films the set into a RenderTexture that the builder shows; the tile pictures are stills from the same studio. Online the set travels as `KartLoadout.Code` (0-3 = a driver's own set like older builds, 100 + 16 driver + 4 kart + tyres for the rest). On the page's first screen `StartLineup` asks the page (`WebPage.FirstScreen`, jslib) whether "Click to play" shows the live game (`cc-live`, wider than 760 px) and then films the four drivers in a row on the right half; the game's own start screen stays hidden until the click.
5. **Countdown and race.** `RaceStateMachine` counts 3, 2, 1, GO (1 s per step, 0.5 s on retry, `RaceSettings.asset`). Every frame `Update` writes `kart.InputEnabled = InputAllowedNow()`, so the kart drives only while Racing. `RaceRoster` switches the bots' input on and off the same way.
6. **Checkpoints.** A relay calls `OnCheckpointEntered(index)`: `rules.PassCheckpoint` for 1..N-1 in order, `rules.TryFinish` at index 0. Each valid checkpoint gives a split against the best lap. R calls `Recover()` (back to the last valid checkpoint, timer keeps running); `FallCheck` does the same below -20 m.
7. **Items.** `ItemSystem` puts rows of boxes after every second checkpoint (`rowEveryCheckpoints: 2`). A box asks `ItemOdds.WeightsFor` (the further behind your best split, the better the item); E uses it through `IKartBoost.AddBoost(seconds, multiplier)`.
8. **Finish.** `FinishLap` stops the timer with `Time.timeAsDouble` (lap = finish timestamp minus start timestamp), gives the medal, saves a record if `RaceModeRules.KeepsRecords`, and starts the slow motion (`FinishMoment`: 1 to 0.3 to 1 over 1.2 s of real time). `FinishCinematic` times the flag, camera swing, headline and results card. A record also saves the ghost (20 samples a second).
9. **Leaderboard.** `LeaderboardHud.OnLapFinished` opens "SAVE YOUR TIME" if the mode uses it and `LapTimeRules.IsAcceptable`. `SaveTypedName` checks the name (`PlayerNameRules`), then `FallbackLeaderboardService` saves on the device first and sends online second. The deployed build carries the two Supabase keys from GitHub secrets, so every player sees the same global top 10; a local build without them keeps times on the device.
10. **Sound.** `KartAudio` crossfades two engine loops by speed (`EnginePitch`) with a pretend gearbox, and plays drift, boost, landing and bump sounds guessed from `IKartState`. `RaceMusic` fades levels in dB per race phase and ducks under beeps; `RaceSounds` answers `RaceManager` events.
11. **Ambience.** When a track loads, `SeasideAmbience` finds the sea by name (`Backdrop_Sea` first), `BeachScanner` walks from the racing line towards the sea with raycasts until the ground drops under sea level, and it builds the wave and surfer meshes (3 surfers riding Rocketbox models through `SurferModelPuppet`).
12. **Online.** `OnlineRaceDirector` joins the room through `IOnlineSession`. The host presses START; `OnlineStartRules` sets GO 4 s ahead on the shared clock and each client calls `BeginRaceExternal` so GO lands at the same moment. Each client sends its pose 15 times a second (`KartPoseCodec`, 33 bytes); other karts are `ProxyKart`s drawn in the past (`PoseBuffer`, `AdaptiveRenderDelay`). Finish order = `FinishOrderRules`; `OnlineRaceLimitRules` ends the race 60 s after the first finish (180 s after GO if nobody finishes).
13. **Build.** `web-build.yml` runs on every push to `main`: it fetches the Photon SDK when the deploy key exists, then GameCI runs `Role4WebBuild.Build`, which rebuilds `Main.unity` (`Role4SceneBuilder`), writes the keys passed as `-leaderboardUrl`, `-leaderboardKey`, `-photonAppId`, sets every Web setting, builds desktop (DXT) and phone (ETC2) data, builds the campus world as its own AssetBundle (DXT + ETC2, named after its content hash) and stamps its file names into `index.html`, and stamps `version.json`. Only `main` is published to GitHub Pages; the `mirror` job copies the same files to the short public link `nova-kart.github.io`.

## Why it is built this way

- **One scene per owner, `Main.unity` rebuilt by code** (Carcavelos Circuit > Build Role 4 Scenes): Unity scenes merge badly (2026-11-07); the builder only rewrites its own root objects (2026-11-08).
- **Rules in plain C# classes** (`RaceStateMachine`, `RaceTimer`, `ItemOdds`, `LapProgress`, `PoseBuffer` ...): Edit Mode tests can check them without a scene.
- **Lap time from two timestamps**, not added-up frame times, which drift by milliseconds (robustness pass, 2026-11-08).
- **The kart only through `Shared/` contracts**: items use the optional `IKartBoost`, so `IKartState` stayed unchanged (2026-11-10); wall bump, take-off and chained boost sounds are guessed from `IKartState` (2026-11-10, audit 11).
- **No AudioMixer**: the Web build only supports mixer volume, so mix and ducking are script maths (`LevelFade`, `DuckEnvelope`, 2026-11-08).
- **HUD in UI Toolkit**, text files like HTML/CSS (2026-11-08); panels are 9-sliced PNG plates drawn by code because USS has no box shadow or gradient (2026-11-11, R15).
- **Device first, online second, Supabase with Row Level Security**: the game must work when the service is down; the public key may only read and insert rows that pass the CHECK rules; keys come only from GitHub secrets (2026-11-11, R10).
- **Online behind `IOnlineSession`**: Photon's licence forbids the SDK in a public repo, so a fresh clone still compiles and plays single player; Shared Mode because Photon recommends it for WebGL (2026-11-16, M2).
- **Ambience finds the sea at runtime**: Luc's scene is never edited, and his sea is one flat 8 km plane, so the beach is found from the ground height (2026-11-11, R12).
- **Web settings in code** (`Role4WebBuild`): some settings are saved per machine in `Library/`, so every laptop built differently (2026-11-08). No compression plus hashed file names because GitHub Pages gzips on the fly (2026-11-08); no static batching and crunched textures to cut the download (2026-11-13, 2026-11-16).
- **Keys**: P pauses, never Escape, because Escape leaves browser fullscreen (2026-11-08, 2026-11-10). Touch controls are HTML buttons that send keys, so no C# changed (2026-11-10).

## Limits

- Medal times are still the placeholder ones (12.0 / 11.0 / 10.2 / 9.6 s for a 158.1 m reference lap, `RaceSettings.asset`), only stretched by track length; the re-tune (task R13) is open.
- No Dean's ghost ships yet: `Settings/DeansGhost.txt` reads "No ghost recorded yet", so a fresh browser races without a ghost until its first record.
- One lap only (`RaceManager.LapCount` returns 1). Bots have no items: `IsKartCollider` counts only the player's kart.
- Leaderboard: a script with the public key can post fake but valid times; a free Supabase project pauses after about a week without requests, which the daily `leaderboard-keepalive.yml` read prevents (`backend/supabase/README.md`).
- Best laps, ghost and settings live in `PlayerPrefs` of one browser; another browser or cleared site data starts fresh.
- Online: 15 players per room (`OnlineRooms.MaxPlayers`), 100 at once on the free plan; a host who walks away blocks the room; karts drive through each other; others are drawn at least 0.22 s in the past (`PoseBuffer.RenderDelaySeconds`); a hidden tab drops out after about 6 s (`docs/online.md`).
- Kart builder: the sets are looks only (no stats, on purpose); the 64 sets are checked by geometry tests (tyres on the ground, no tyre inside the body, hands on the rim) but driver vs roll cage is only checked by eye; tiles and the turntable are filmed at run time (a weak phone pays one extra camera while the builder is open); the first-screen line-up shows only above 760 CSS px width (narrow phones keep the key art).
- Sound guesses use first-guess thresholds (wall bump = 4 m/s drop in one frame and over 60 m/s2, decision 2026-11-10).
- The Web frame rate without static batching was not measured in a visible browser (decision 2026-11-16, V37). In portrait the HUD is clipped; iPhone Safari has no page fullscreen.

## How it could change

- **More laps:** finish only after N crossings of checkpoint 0 in `RaceManager.OnCheckpointEntered` and return N from `LapCount` (the HUD already shows a lap counter above 1).
- **A new item:** a value in `ItemKind.cs`, a column in the `ItemOdds` weight rows, its effect in `ItemSystem.cs`, its numbers in `ItemSettings.asset`.
- **Stop fake times:** insert through a Supabase Edge Function that checks the lap (`backend/supabase/`, `SupabaseRequests.cs`) and take INSERT away from the public key.
- **A fifth kart or tyre:** Luc's prefab `KartVisual_<Kart>_<Driver>` with the same seat and wheel anchors, one more entry in `DriverRoster` and in the four lists of `KartLoadout` (the code format then needs 5 x 5 x 5: change `CustomBase` maths and its tests).
- **Another network service:** one new `IOnlineSession` class registered in `OnlineSessions`; `OnlineRaceDirector` stays as it is.
- **Final tuning:** new medal times and reference length in `RaceSettings.asset`, then Carcavelos Circuit > Save My Best Ghost As Dean's Ghost (`Editor/DeansGhostExporter.cs`).
