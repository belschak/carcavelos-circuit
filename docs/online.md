# Online race (task M2)

Everyone in the class joins the live game from the one link, joins the one room and races the others. Decided in the group chat on 16 Nov (Luc proposed Photon Fusion 2), details in `docs/decisions.md` (2026-11-16). Since the team test on 17 Nov there is ONE room for the whole class (it was a noon and a sunset room): see "One room" below.

## For players
1. Open the live link (top of the [README](../README.md)) and pick **ONLINE RACE** on the start screen.
2. Build your kart (driver, kart, tyres: the same builder as offline), type a name, then press **JOIN RACE** (or Enter). The room takes 15 players, first come first served; a full room says so: try again after the race that is running. Noon or sunset is your own look (**T** or the LIGHT button in the lobby, T on the start screen); the others see their own light.
3. Everyone sees everyone else in the set they built (any of the 64 driver + kart + tyre sets; looks only, every set drives the same). The name tag and the minimap dot carry the player's room colour, so two players with the same driver stay apart.
4. The host (the first player in the room) presses **START RACE**. Everyone counts down to the same GO. One lap. Your own kart drives exactly as offline; the others are shown as they drive.
5. The finish order is the same on every screen (lap times, leavers count as DNF). After the first player crosses the line the others have 60 s to finish (180 s after GO if nobody finishes); then everyone still driving is DNF and the results are final. The host can start the next round only once the race is over for everyone; **Q** leaves the room.
6. Keep the tab in front: a browser tab in the background gets no frames from the browser (the kart stops, nothing is sent) and drops out of the room after a few seconds.

Online mode has no bots, no ghost, no leaderboard saving and no pause when the window loses focus. Items work online since 17 Nov 2026 (PR #140): every player has their own boxes, and every item acts only on the player's own kart (boost, rings, shield), so the others see the speed-up through the synced position.

## One room (17 Nov 2026)
- We run no servers: Photon Cloud hosts the room, and the free plan counts players (100 at once), not rooms, so one room or two cost the same.
- Two rooms split a class of at most 15 into two half-empty races; one room puts everyone into the same race.
- The light was the only difference between the rooms, so it became each player's own look (local, never sent). The old links `?room=noon` and `?room=sunset` open the one room with that light for the visit; the session name is new (`carcavelos`), so a page still on the old two-room build never meets the new one.

## Never a dead end (20 Nov 2026, before the presentation)
- **Network:** in the browser every Photon connection is a secure WebSocket on port 443 (name server `wss://ns.photonengine.io`, master and game server `wss://gcams*.exitgames.com`), so a campus network that blocks UDP or unusual ports still lets the race through like any HTTPS page. Only a network that blocks Photon's host names stops it: the message then says to try another Wi-Fi or a phone hotspot.
- **More than 15 players:** room 1 full -> the lobby goes on to `carcavelos-2`, then 3 and 4 by itself ("ROOM 1 IS FULL, JOINING ROOM 2..."); each room races on its own (60 seats, under the 100 CCU). `?room=2` joins room 2 straight away.
- **A join that fails:** 5 tries by itself, 2/3/5/8 s apart (`OnlineJoinRetry`), RACE THE BOTS already on the connecting page while it tries again; then the message with TRY AGAIN (Enter), RACE THE BOTS and BACK. Also when every room is full.
- **The host does nothing** (a phone in a pocket): with 2+ players the room starts by itself 90 s after the last player joined, and the next round 45 s after a race is over (`OnlineStartRules.RoomAutoStartAt`); the host can always start earlier. The lobby shows "RACE STARTS BY ITSELF IN N S". Not with the `?autostart=N` test flag.
- **Same name twice:** the later one shows as "ANA 2" in the lobby, on the name tag and in the results (`OnlineNames`).
- **A page from an older build** (a tab left open over a deploy): opening the lobby checks `version.json` and reloads into the newest build with the same name, back in the lobby by itself (`OnlineBuildCheck`, never in the middle of a lap).
- Test flag `?seats=N` (2..15): small rooms with their own names (`carcavelos-sN`, `carcavelos-sN-2`), so a few tabs can fill and overflow a room without touching the class room.

## How it is built
- `Assets/_Project/Online/` (assembly `CarcavelosCircuit.Online`, always compiled): lobby UI, room rules (`OnlineRooms`), URL flags (`OnlineUrlFlags`), pose codec + buffer, proxies (`ProxyKart`), race control (`OnlineRaceDirector`), all against the `IOnlineSession` interface. No Photon types here, so the public repo compiles and plays single player without the SDK.
- `Assets/_Project/Online/Fusion/` (assembly `CarcavelosCircuit.Online.Fusion`, define constraint `CARCAVELOS_FUSION`): the Photon Fusion 2 Shared Mode implementation of `IOnlineSession` (region eu, session name `carcavelos` or an overflow room `carcavelos-2..4`, PlayerCount 15). Each player's networked state carries name, room colour, driver set (`DriverIndex`, which since #170 carries `KartLoadout.Code`: 0-3 for a driver's own set, 100-163 for a built set), pose and finish.
- RaceFlow only knows `RaceFlow/OnlineRaceHooks.cs` (`Available`, `UnavailableMessage`, `OpenLobby`) plus the small external-start API on `RaceManager` / `RaceRoster` (`docs/interfaces.md`).
- Test transport without Photon: `?net=local` uses a `BroadcastChannel`, so several pages of the same browser on one machine form a room. Other URL flags for tests: `?room=carcavelos` (the old `?room=noon|sunset` still work: same room, and that light for the visit), `?name=X` (auto-join), `?autopilot=1` (the own kart drives itself), `?autostart=N` (the host starts 5 s after N players joined), `?render=0` (cameras off, for scale-test bots on machines without a GPU: they still drive and send at full frame rate). Example: `index.html?net=local&room=carcavelos&name=A&autopilot=1&autostart=2` in two windows (second one with another name).
- Local tests need separate, visible browser WINDOWS side by side (one page each, none minimised), not several tabs in one window. A hidden tab gets no frames (`Application.runInBackground` only helps a visible page without focus), so it stops sending, drops out of the room after about 6 s (DNF on the other screens), never answers a newcomer and its kart freezes; it re-joins when it is shown again.

## The SDK is not in the repo
Photon's licence terms do not allow redistributing the SDK (https://www.photonengine.com/terms/licenseterms, sections 10.2 and 17), so `Assets/Photon/` is gitignored. The Web build on GitHub Actions checks the SDK out of the private repo `belschak/carcavelos-photon-sdk` with a read-only deploy key (secret `PHOTON_SDK_DEPLOY_KEY`) into `Assets/Photon/`, and `OnlineBuildConfig` sets the define `CARCAVELOS_FUSION` plus the App ID from the secret `PHOTON_APP_ID` (checked to be a GUID, written to `Online/Resources/CarcavelosPhotonAppId.txt` only during the build, like the leaderboard keys). Without the two secrets the build is single player only; nothing fails.

The App ID is not a secret in the strict sense (every Photon client build contains it), it just stays out of commits so it cannot be scraped from the repo.

## For developers: the online race in your local editor
1. Free Photon account at https://www.photonengine.com, download **Photon Fusion 2.1.4** (`.unitypackage`) from https://www.photonengine.com/sdks#fusion and import it into the project (it lands in `Assets/Photon/`, which Git ignores).
2. The first import adds the package `com.unity.nuget.mono-cecil` and the `FUSION_*` defines by itself and creates `Assets/Photon/Fusion/Resources/NetworkProjectConfig.fusion` + `PhotonAppSettings.asset`.
3. Add `CARCAVELOS_FUSION` to Project Settings > Player > Scripting Define Symbols (WebGL and Standalone); without it the assembly `CarcavelosCircuit.Online.Fusion` is skipped and Online says it needs the online build. Weaving needs no setting: the asmdef carries `FUSION_FORCE_WEAVING` (and the private SDK copy used by CI also lists the assembly in "Assemblies To Weave").
4. App ID: ask David for the Fusion App ID of the "Carcavelos Circuit" app (or create your own free Fusion 2 app in the Photon dashboard) and put it into `Assets/Photon/Fusion/Resources/PhotonAppSettings.asset` (App Id Fusion) or into `Assets/_Project/Online/Resources/CarcavelosPhotonAppId.txt` (ignored by Git).
5. Play: pick ONLINE RACE. For a two-player test on one machine, build to WebGL and open the link in two visible browser windows side by side (not two tabs of one window, a hidden tab drops out), or use `?net=local` the same way in the Web build without Photon.

## How it is tested
- Edit Mode tests cover the rules under the transport: pose codec + buffer, race control codec, rooms, URL flags, start rules (late-control countdown, host start only when the race is over), race time limit, proxy visibility, finish order (ties, DNF), loopback session (join, full room, master hand-over, leave, drivers travel with the player, 15 in one room), overflow rooms and test seats, same-name tags, the room starting by itself, TRY AGAIN / RACE THE BOTS on the message page (`OnlineUnbreakableTests`), the CCNET lines (RESULT, the RACE line's `karts=` list of every other kart's driver and model).
- No test can reference Fusion (the public CI has no SDK), so the Photon adapter is tested by the CI Web build plus two or more browser tabs on the live link.

## Limits
- Players: 100 concurrent users (CCU) on the one App ID (checked in the Photon dashboard on 16 Nov 2026: Fusion app "Carcavelos Circuit", Public Cloud, 100 CCU, 300 GB traffic; Photon's free 100 CCU offer, no paid subscription). Every open game page in a room counts, also a forgotten tab. Above 100 Photon refuses the connection (`MaxCcuReached`), the game shows "server full". A room holds 15 players; more players fill rooms 2 to 4 (60 at most).
- Remote karts are drawn 0.22 s in the past (`PoseBuffer.RenderDelaySeconds`) and blended between poses; if poses stop, a kart keeps going straight for at most 0.3 s, then holds. 0.12 s was too tight for campus Wi-Fi (Luc's review): a pose needs the send gap (67 ms) plus the trip through Photon (Amsterdam) plus jitter. Our two-window test on one PC could not show this, the trip there is near zero. Since the scale test (17 Nov 2026) 0.22 s is the minimum: each remote kart measures how old its newest pose is and draws itself at the 95th percentile of the last 3 s of these ages + 30 ms (`AdaptiveRenderDelay`, at most 0.8 s), because over real Photon the newest pose was older than 0.22 s in 29 to 45 % of the frames.
- The host (first player in the room) starts every race. A host who walks away blocks the room until they leave (Q or closing the page hands the host role to the next player). For the class demo one of us hosts the room.
- Campus Wi-Fi: WebGL talks WebSocket (TCP) on 443, so packet loss shows as short freezes of other karts, never of your own. Poses are sent 15 times a second, about 30 bytes each.
- Joining a room takes about 8 s on a fast PC (Photon name server, master, game server, relay) and longer on a slow laptop or busy Wi-Fi; the game waits up to 35 s before it says the server did not answer (scale test, 17 Nov 2026: the old 15 s cut off slow clients).
- A failed or timed-out join, and a connection lost later, is tried again by itself up to 5 times, 2, 3, 5 and 8 s apart ("CONNECTING AGAIN (TRY 2 OF 5)", `OnlineJoinRetry`; 3 tries 2 s apart until 20 Nov 2026); never for a full room/server, a refused App ID or version, or the player's own cancel. Scale test 17 Nov 2026: two clients on one machine got ERR_CONNECTION_RESET from Photon's game server while ten others joined.
- A backed-up connection (the newest data of at least 3 in 4 other karts older than 5 s for 3 s, with at least 2 others in the room; `ConnectionHealthRules`) leaves and joins again with a fresh connection through the same retries. Scale test 17 Nov 2026: a client with 300 ms +- 80 ms jitter AND 1 % loss got everything later and later (GO 35 s late after 10 min); 300 ms alone, jitter alone, 300 ms + 1 % loss and 150 ms + 3 % loss were all fine.
- Test lines: every client prints `CCNET ...` lines to the browser console (`OnlineTestLog`: JOIN, HOST, RACE, GO with its skew from the shared start, FINISH, RESULT with the full finish order, STAT every 10 s with fps and how often a remote kart ran out of poses). The scale test compares them across all clients.
- Karts drive through each other online (no physics between players), on purpose: it keeps every client's own drive honest and simple.
